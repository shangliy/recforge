# Evaluation audit of self-evolving recommender systems

Data behind the audit section of the survey (the audit table, the summary figure, the cross-tab and the table that checks the reporting checklist retrospectively, by proxy, against the coding). Coded from 2026-10-21 onwards from the full text (arXiv HTML or PDF, with
appendices) of each paper, in the version listed in the `version` column (current at the 2026-10-22 cut-off).

- `audit.csv`: one row per system; the paper's audit table and every coded audit count are generated from it by `summarize.py`. Not recomputed from coded cells: the design table (assembled by hand from `design.csv`), and the judgement-based sets (agent-introduced incidents, stated catchers, same-space and strict null controls), which `summarize.py --headline` names explicitly; the F8 lifts were read by hand from the papers into `f8-lifts.md`, one row per loop, and `summarize.py --headline` counts them and prints their range.
- `evidence-part1.md`, `evidence-part2.md` (RecEvolve appears in both, from two reading passes; the released codes at the top of each section are the same): per-paper rubric with verbatim quotes (at most 25 words) and section or
  table pointers for every coded cell. These files record the first coding's reading; where a cell was recoded later (marked ⟨recoded⟩ with its released code), the flag carries the supporting quote for the released code at the cell, taken from the second coder's returned notes (`second-coder/returned/`) where the released code is that coder's (52 of the 63 flags across `evidence-part1.md`, `evidence-part2.md` and `evidence-part3.md`; RecEvolve is written up in both part 1 and part 2, so its three flagged cells, C1, C5 and C9, are each flagged twice); for the other eleven flags the flag points to `second-coder/reconciliation.md` or `verification-pass-1.md`, where the reason for the recode is argued. `CHANGELOG.md` lists every recoded cell.
- `evidence-part3.md`: the same for the systems added in the second sweep (the data file is authoritative where they differ).
- `evidence-online-gates.md`: quotes behind the online-gate columns (`ab_*`).
- `evidence-released.md` (generated by `evidence_released.py`; do not edit): a flat view with one row per scored cell of the 27 core loops and 7 comparison points, giving the released code and only the evidence that supports it now, without the superseded verdicts kept in the files above. Its coverage line states the count: every one of the 82 credited (`Y` or `P`) cells carries a quote and pointer, as do the three C8 cells coded `tuned` (which count as yes); the 6 cells that carry only a pointer to the file arguing their recode are all uncredited (`NS`, `N`, `other`, `online` or `test`). For 21 credited cells the first-coding note paraphrased the paper; on 29 October 2026 a verbatim quote (at most 25 words) was added to each from the coded arXiv version, matched by normalised string search against that version's text, and placed before the note. The quotes are in `quotes-added.json`. Two notes were corrected at the same time because their paraphrase overstated the source (EvoSkillRec C9: static analysis, not a sandbox; Feedback Contract C5: the gap is one of three reported metrics, not the primary one); neither code changed.
- `design.csv`: design fields (proposer, acceptance rule, guards, kept edits, headline gains), single-coded. Proposer `learned+llm` (DMRL: an RL-trained LLM writes the skill document a frozen LLM agent follows) is counted as learned in the paper's tables. In `signal_chain`, the starred stage is the one that decides inside the loop, not the audit stratum: Sortify (`proxy*`, rounds chosen online) and DMRL (`proxy*`, a long-term predictor applied to online experiment outcomes) are online-selecting in `audit.csv`, as is GEARS (`online*`, estimates from a completed randomised experiment); the paper's design table caption gives the reasons.
- `recall-check.md`: backward-citation recall check of the search (systems cited by the core papers).
- `verification-pass-1.md`: fact check from the first verification pass, which corrected 12 cells before the data file was first committed (rows of the first sweep).
- `verification-pass-3.md`: fact check of the seven rows added in the second sweep, which the earlier passes did not cover, and of the survey sentences that cite them.
- `annotate_evidence.py`: writes, under each system's heading in the three evidence files, its released codes from `audit.csv`
  and the cells recoded since first coding (from `CHANGELOG.md`), and appends the released code (with the second coder's quote where it is that coder's code) to each body line of a
  recoded cell, so a superseded verdict in the text is not taken for the released one; rerun after any change to `audit.csv`.
- `CHANGELOG.md`: every change to a cell of `audit.csv` after the first coding, generated by `changelog.py` (which needs the repository's git history; where that history is not available, `CHANGELOG.md` is its output).
- `second-coder/`: the second coder's sheets, the first coder's pre-reconciliation sheet, `kappa.py`, the coder guide and the reconciliation log.
  `online-gates-check.csv` is a blind re-coding of the `ab_*` columns by a separate LLM agent that had no access to the first coding (a consistency check, not a human second coding); `online-gates-coder1-preadjudication.csv` is the first coding of those columns before adjudication, and `online_agreement.py` computes the agreement.

## Codebook
| column | values |
|---|---|
| set | `core` (recommendation, L1–L3 loop with evaluation-driven selection) or `comparison` (outside recommendation) |
| level | evolved object: `L1` configuration, `L2` code, `L3` generative-recommender components (joined with `+`) |
| meta | `Y` the loop changes its proposer's instructions, tools, skills or weights and reuses them; `N` |
| evaluator | `Y` the loop's evaluator (feedback code, objective or reward model) changes during the run; `N`; `na` comparison points |
| c1 metric | `full` full-catalogue ranking; `sampled` ranking against sampled or in-batch negatives; `ranking-ns` ranking with the candidate set not stated; `auc` AUC/logloss/loss proxy; `online` online only; `none` no usable metric stated; `other` a non-recommendation metric |
| c2 selection | the data or signal that keeps or rejects candidates in the loop: `val`; `test` (the same data the results are reported on); `trainloss`; `online`; `NS` (not stated); `na` (no selection step: operational outcomes only) |
| c3 test once | `Y` stated; `N` selection data are the reported data, or test is reused; `P` partly; `NS`; `na` (online-selecting loops) |
| c4 repeats | `Y` repeated evolution sessions with spread; `P` repeats without spread, ablation-only repeats, a re-run rule, or a run-to-run noise estimate of single models without repeating a session; `N` |
| c5 gap | `Y` explicit selection-vs-held-out check of the selected candidates; `P` partial transfer evidence (another dataset, scale, period or population); an offline-selecting loop whose `P` rests only on an online confirmation of the kept candidate (`online` not `none`) is shown as `O` in the paper's audit table and drawn apart in its figure, since it tests transfer rather than overfitting to the selection data; `N` |
| c6 null | `Y` non-LLM search (random, grid, BO, HPO, NAS) at equal or favourable budget; `P` partial (unmatched budget, LLM still proposing, replay only); `N`. The second-coder guide asked for a search "over the same space"; the one Y this changes is EvoSkillRec (NASRec searches architectures, not its code-and-skill space), so the same-space count is 2, and a reader who also requires a matched total budget, LLM cost included (R5), counts 1 (VirtualMLE; paper, F6 and Table 7) |
| c7 budget | units reported (free text, not scored) |
| c8 baselines | `tuned` (stated); `P` partly tuned, or tuned on the test split; `untuned`; `production`; `published`; `seed`; `NS` |
| c9 isolation | design, regardless of incidents: `Y` stated that the agent cannot reach test data or labels; `P` part of the loop constrained (fixed evaluation code, gates, whitelists, sandboxing, bounded actions); `N` the agent can reach test data; `NS`; `na` online-only loop with no offline data or evaluation code the agent could touch and no stated constraints |
| incident | `Y` the paper reports gaming, metric inflation, leakage or a metric-winning bug in the loop's own evaluation of a candidate, whoever introduced it (the agent in three of the four `Y` rows; EvoPilot's paper does not say whether the agent or a person chose the leaky date); `N` |
| online | `none`, or what is reported: duration (`7d`, `3wk`, `1mo`), `CI` or `sig` (confidence intervals or significance), `yes` (an online experiment without either) |
| code | `Y` released; `promised`; `N` |
| llm_named | `Y` the LLM is named; `N` |
| ab_role | online experiments: `select` the loop keeps or rejects candidates on A/B results, `confirm` one offline-selected candidate is A/B-tested, `both`; `na` no A/B |
| ab_rounds | number of online rounds tested (`NS` not stated) |
| ab_duration, ab_ci | duration stated; confidence interval, significance test, or an explicit claim of statistical significance for the headline online result (`Y`/`N`/`NS`; assertion-only cells are marked significance-only in evidence-online-gates.md) |
| ab_correction | a correction for multiple testing across rounds (`na` for `confirm`) |
| ab_confirm | the reported online effect comes from an experiment separate from the selecting rounds (`P`: designed or asserted but not reported, or separation not stated). Evidence: evidence-online-gates.md (single-coded) |
| version | arXiv version coded (also the latest as of 2026-10-22) |

Strata used in the paper: offline-selecting loops (`c2` not in `online`, `na`; 16), online-selecting loops (`c2` =
`online`; 10) and one loop with operational outcomes only (`c2` = `na`). All counts, the audit table and the summary figure are generated
by `summarize.py`.

"Not stated" means the paper does not say; it does not mean the practice was absent. Corrections are welcome as
issues or pull requests with a quote from the paper.

## Reconciliation with the second coder (2026-10-23)

A second author coded all 27 core systems separately, by hand without an LLM by the coder's account (the guide asked the coder not to open the first coding's sheet; `second-coder/returned/`; 17 first-coding cells were nonetheless visible in the codebook file it was pointed to, including the four incident codes, see `second-coder/README.md`; the guide's opening still says "10 papers" and "eight criteria" from its first batch, as that README explains). Pre-reconciliation agreement:
per-criterion Cohen's kappa is the primary statistic (paper, Table 7); summarised with chance agreement taken within each criterion, kappa is 0.68 over the 16 offline-selecting loops and 0.71 over all 27 (raw agreement 0.84 of 243 cells; pooled over all cells 0.81, which overstates agreement; Gwet's AC1 0.84); kappa below 0.6 for c5 (0.30) and c8 (0.57). The 38 disagreements
and their resolutions are in `second-coder/reconciliation.md`; 31 cells changed in this file. The first coder's sheet as
it stood before reconciliation is `second-coder/coder1-prereconciliation.csv` (from commit 925fd50); `python3 kappa.py
--first coder1-prereconciliation.csv returned/coder2.csv returned/coder2-part2.csv` reproduces the figures above, and
without `--first` the same command gives the post-reconciliation agreement (pooled kappa 0.97). For the first coding,
LLM agents extracted a quote per cell from the full texts and the first author coded each cell from that quote and its
context, checked against the paper text but without a full reading of every paper; the second coder read every paper by
hand; `second-coder/README.md` gives the exact statement of what the coder did and did not view, identical to the paper's. LLM agents drafted a resolution for each disagreement
with a quote, which the authors reviewed. One adjudication was overridden: EvoSkillRec c3 was upheld as `Y` in
Adjudication A and set to `N` under the literal codebook wording ("used during search or repeatedly"); under `Y`, the
paper's F3 count would be 3 rather than 2. Google/YouTube is now
online-selecting (c2 `online`), so the strata are 16 offline-selecting, 10 online-selecting, 1 operational.

Rules the reconciliation settled, to apply to new rows. They were written during reconciliation, after both codings
were complete, so they are post hoc for the 27 coded rows; the coder guide used by the second coder is in
`second-coder/CODER-GUIDE.md`:
- c2 in a multi-stage loop: code the last gate that keeps or rejects among several candidates. A single online test of
  one already-selected candidate is c5 evidence, not selection.
- c1: the headline metric is the one behind the numbers in the abstract's headline claim; `online` only when every
  quantified gain there is online; `other` for any non-recommendation metric (fix steps, policy-selection nDCG);
  `none` only when no quantitative metric is given. A success rate defined on a recommendation metric (NOVA's EPR on
  AUC) is coded by that metric.
- c3: `N` when test scores are computed during the search or the reported number is by construction the best over
  rounds, even if the paper states they are not used for selection.
- c5: an online A/B of an offline-selected candidate, or a check on another dataset or scale, is `P`; `Y` is reserved
  for a same-task selection-vs-held-out comparison. A designed but unreported confirmation, or a check of a proxy rather
  than of the selected candidates, is `N`.
- c6: comparisons with humans, manual workflows, other LLMs or trivial decision rules are `N`.
- c8: `P` if tuned on the reported split; else `tuned`/`untuned` if tuning is stated (original-paper defaults are
  `untuned`); else the comparator's identity (`seed`, `production`, `published` only for numbers copied from papers).
- c9: `N` when the text shows the agent reading test labels or running test evaluation, whatever the process gates.
- incident: requires a documented instance; a risk the paper names (AutoLR's KEEP ratchet) is a note, not `Y`.

## Changes in v2 (2026-10-22, after review)

- `c9` no longer mixes design and incidents: the four core rows formerly coded `gaming` now carry their isolation
  design (RecEvolve `P`, RankEvolve-HSTU `N`, EvoPilot `P`, Amazon AutoResearch `P`) and `incident` = `Y`; AI
  Co-Scientist is `NS` + `Y`.
- EvoPilot `c2` NS → `test`, `c3` NS → `N`: one held-out replay set both selects and is reported (§5.1).
- Population Evolution `c2` NS → `test` (source-instance evaluation scores drive discovery and report local gains;
  transfer targets are withheld from the proposer) and `c8` tuned → `P` (baselines calibrated on the released test
  split, App. F.1).
- A/B Agent meta → N: only its experience tree of past outcomes is written back.
- `level` now holds the evolved object only, and meta-evolution has its own `meta` column (Y for 13 core systems at the time; 11 since Self-EvolveRec and Sortify moved to the `evaluator` column,
  following the rule in design.csv: the loop changes its proposer's instructions, tools, skills or weights and reuses
  them). Object changes: EvoRec L2 → L1+L2, RecHarness and NOVA L2 → L1+L2, AgentX L2 → L1+L2, Amazon AutoResearch
  L2+L3 → L1+L2+L3 (their kept edits include configuration and strategy parameters).
- `c9` for CORAL, AgenticRecTune, Sortify and GEARS `na` → `P`, and Google/YouTube `NS` → `P`: each states
  constraints on the loop (bounded changes, critic and review gates, read-only sandboxes, a fixed scoring loss).
- Design fields for every core system (object, proposer, signal chain, memory, acceptance, guards, human role, LLM,
  kept edits, headline gain, baseline) are in `design.csv`, with evidence quotes in `design-evidence.md`.

## Provenance of cells

`audit.csv` is authoritative. Evidence files record the reading at the time a row was first coded; later recodings
(review rounds, reconciliation) are listed cell by cell in `CHANGELOG.md`, generated from the git history by
`python3 changelog.py > CHANGELOG.md`. The `version` column gives the arXiv version that was coded; for every row it is
also the latest version as of the 2026-10-22 cut-off.
